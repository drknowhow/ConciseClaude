# 5.0 vs 4.0 benchmark, 2026-10-04

This run checks whether the 5.0 fixes worked, and whether they cost anything. It
compares no plugin (default), the 4.0.0 plugin and 5.0.0 on Sonnet, Opus and
Haiku, using Claude Code 2.1.289 headless. Each model ran 14 single-turn
question types, two six-turn conversations and three coding tasks, twice each,
for 522 replies. A separate Sonnet session graded the 252 single-turn replies
blind against 4–7 key points per question.

Cost and output below leave out the depth question, because 5.0 is meant to
answer it at length.

| Model | Key points covered (default / 4.0 / 5.0) | Cost vs default, 4.0 → 5.0 | Output vs default, 5.0 | Protected label, 4.0 → 5.0 |
|---|---|---|---|---|
| Sonnet | 98% / 87% / 94% | −4% → −6% | −37% | 44% → 21% |
| Opus | 99% / 93% / 93% | −24% → −30% | −57% | 44% → 33% |
| Haiku | 75% / 71% / 72% | +2% → −4% | −23% | 8% → 6% |

Each fix, checked against its own evidence:

| Fix | Measure | Default | 4.0 | 5.0 |
|---|---|---|---|---|
| Depth | Sonnet output tokens for "explain in depth" | 7,973 | 968 | 7,812 |
| Depth | Opus output tokens for the same question | 16,392 | 4,966 | 11,674 |
| Look first | Sonnet suggests `docker system df` or a backup before pruning | 2/2 | 1/2 | 2/2 |
| Look first | Haiku fetches main before deleting merged branches | 1/2 | 0/2 | 2/2 |
| Review | Sonnet flags the unclosed cursor | 2/2 | 0/2 | 2/2 |
| Drafts | Sonnet PR description covers testing (graded too terse: 4.0 2/2, 5.0 0/2) | 2/2 | 1/2 | 2/2 |
| Input | Sonnet input tokens per call | 4,478 | 7,038 | 6,503 |

On Sonnet, 18% of 4.0 replies were graded too terse; on 5.0, none were. Tests
passed in every coding run. Code written after the rules moved to on-demand
loading carried 0–4 comment lines per model, against 0 on 4.0 and 0–19 on
default, and the diff meter found nothing. One checklist point still misses on
Haiku: it never flagged the unclosed cursor (0/2 on both plugin versions).
The benchmark cost $31.98 and grading $5.53, at API-rate estimates.
