# Token, cost and speed A/B, 2026-10-03

Does the Concise style save tokens, money and time, or does it only make
replies shorter? Two controlled runs with headless Claude Code answer that.

## Setup
- Claude Code 2.1.288, model `sonnet`, Windows 11, ConciseClaude 3.1.0.
- Each turn is a `claude -p` call with `--setting-sources project`, so the
  tester's own user settings, hooks and plugins stay out. Multi-turn
  conversations continue with `--resume`.
- **on**: output style Concise. In the multi-turn run it also had the
  `reply_shape.py` Stop and UserPromptSubmit hooks in nudge mode, logging to a
  scratch directory.
- **off**: the default output style, no hooks.
- The tester's `~/.claude/CLAUDE.md` loaded in both arms, and it contains the
  three-line pointer to these rules. The off arm was therefore already nudged
  toward short replies, so the savings below are a lower bound.
- Runs went six at a time in shuffled order, so both arms saw the same load.
  Wall time includes process start-up.
- Harness: [`bench/ab.py`](../bench/ab.py). Raw rows:
  [`data/token-ab-2026-10-03-single.json`](data/token-ab-2026-10-03-single.json),
  [`data/token-ab-2026-10-03-multi.json`](data/token-ab-2026-10-03-multi.json).
  Cost is Claude Code's `total_cost_usd`, the API-rate equivalent.

## Single turn
Eight questions (explanations, debugging, a recommendation, a plan, a code
review) twice each with no tools, plus a small coding task (write `slugify.py`
and its tests, run them) three times with tools.

| | Output tokens off → on | Change | Reply chars | Cost off → on |
|---|---|---|---|---|
| Questions (16 runs per arm) | 12,765 → 10,455 | −18% | −23% | $0.40 → $0.40 |
| Coding task (3 runs per arm) | 3,008 → 2,609 | −13% | −51% | $0.12 → $0.14 |

Per question, output changed by between −41% (the Postgres-or-SQLite
recommendation) and +2% (the rate-limiting plan). The style adds about 480
input tokens per call. In a single cold call, writing the prompt cache costs
more than the shorter reply saves, so cost came out even.

## Six-turn conversations
Three scripted conversations, each run three times per arm: ops
troubleshooting (nginx 502s), schema design (a habit tracker), and a coding
project with tools (a todo CLI with tests, then a refactor).

| Conversation | Output tokens | Cost | Wall time | Reply chars |
|---|---|---|---|---|
| Ops | 16,618 → 10,908 (−34%) | $1.12 → $1.00 (−11%) | 198 s → 170 s (−14%) | −61% |
| Design | 24,699 → 12,925 (−48%) | $1.40 → $1.09 (−22%) | 267 s → 201 s (−25%) | −58% |
| Coding | 17,738 → 18,703 (+5%) | $1.74 → $1.78 (+2%) | 208 s → 194 s (−7%) | −27% |
| **All** | 59,055 → 42,536 (**−28%**) | $4.25 → $3.87 (**−9%**) | 673 s → 566 s (**−16%**) | −56% |

Cost per session, three runs each, to show the spread between runs:

| Conversation | off | on |
|---|---|---|
| Ops | 0.388, 0.357, 0.370 | 0.318, 0.331, 0.347 |
| Design | 0.485, 0.466, 0.449 | 0.361, 0.385, 0.344 |
| Coding | 0.568, 0.592, 0.577 | 0.609, 0.615, 0.560 |

In ops and design every on run cost less than every off run. In coding the
two arms overlap, so that result is a wash.

## What it means
- **Conversation is where it pays.** Replies are about 60% shorter, so each
  later turn has less to generate. Wall time falls with it, by less, since
  generating output is the slowest part of a turn but not all of it.
- **Coding sees no saving.** Most of the output there is tool calls and file
  contents, which the style doesn't shorten. The final replies were still
  shorter, but tool steps made up the difference.
- **Input goes up a little.** The on arm read about 14% more cached input,
  from the style text and the nudge note. Cache reads are billed at a tenth
  of the normal input rate, so the net cost still fell.
- **Limits.** One model, three runs per arm, scripted prompts, and the
  CLAUDE.md pointer in both arms. Other models weren't measured.

## Reproduce
Needs `claude` on PATH and the style installed at
`~/.claude/output-styles/concise.md`. Each run spends real usage: the multi
suite is 108 turns.
```
python bench/ab.py run --suite single --reps 2 --out single.json
python bench/ab.py run --suite multi  --reps 3 --out multi.json
python bench/ab.py summary multi.json
```
